# DXSO corpus

Shader cache files (`mtld3d_shaders.bin`, the layer's own format) holding DXSO tokens, their exact
specialization and the pipeline recipes that pair vertex and pixel shaders. The C3a parity test renders every
recipe through D3D9's MSL and through `airconv::dxso::translate`. No game shader is in any of them.

| File | Origin | Licence | Shader records | Pipeline recipes |
|---|---|---|---|---|
| `synthetic.bin` | the hand-assembled SM1-SM3 set of `emit_corpus` plus 14 `ps_1_x` texture-address programs (bem, texbem, texbeml, texm3x2*, texm3x3*, texreg2*, texdp3*, texdepth; paired with the `vs_1_1` shaders only) 9 modifier programs (`_sat`, negate, abs, `1-`, `_bias` feeding more arithmetic, three vertex and six pixel shaders, whose 20 recipes render into `Rgba16Float`) and 7 depth writers (the four `ps_1_4` `texdepth`/`texm3x2depth` programs again without `NO_DEPTH_ATTACHMENT`, and three `ps_2_0`/`ps_3_0` programs that write `oDepth` from a varying, one with `_sat`; each in one recipe with a `Depth32Float` attachment, read back and compared; the `ps_1_4` ones pair with a fourth `vs_1_1` that also writes `oT2`, so `texm3x2depth`'s depth varies), none in `--digest`; and the fixed-function keys of `synthetic_ff` and `synthetic_ff_extra` (clip planes, blending, pre-transformed passthrough, point size, spot lights, every TCI mode, texture transforms, vertex fog, every colour and alpha op, TEMP, bump environment stages, depth, cube and volume slots, LOD bias, raw and projected depth) as MSL records with their sources, each vertex key drawn with a pixel key that shows its outputs and each pixel key behind a vertex key with eight four-component coordinate sets (a projecting one also behind one whose projected `w` is zero), plus cross-family pairs (a fixed-function vertex stage before every programmable pixel shader, `vs_1_1`/`vs_2_0`/`vs_3_0` before a fixed-function pixel stage, a pre-transformed passthrough vertex stage before a `ps_3_0` reading its extras); generated by `--write-cache` | Zlib (this folder's `LICENSE` is `tests/d3d9/LICENSE`) | 403: Sm1Vs 4, Sm1Ps 26, Sm2Vs 4, Sm2Ps 9, Sm3Vs 3, Sm3Ps 7, FfVs 168, FfPs 182 | 521 (362 with a fixed-function stage) |
| `conformance-x64.bin` | the shader caches of Wine 11.20's `d3d9_test.exe` (x64), run by the conformance runner on the arm64x leg (device, visual, d3d9ex; stateblock creates no programmable shader), merged | Wine's d3d9 tests are LGPL-2.1; this folder is under `tests/d3d9`, whose `LICENSE` is Zlib, and the repository README's licence list names this folder | 211: Sm1Vs 26, Sm1Ps 48, Sm2Vs 38, Sm2Ps 27, Sm3Vs 17, Sm3Ps 55 | 149 |
| `conformance-i686.bin` | not present yet: the i686-arm64 leg did not run (see below) | LGPL-2.1 | - | - |

`triaged.txt` lists recipes the parity test accepts as different, one `<file> <vs key> <ps key> <reason>` per line.

The parity test renders a fixed-function record's MSL from its key (`ShaderSource::emit`) and its AIR from the
tokens `ff_build` made, with fixed-function inputs (the layer's constant layout for a fixed transform, lighting, texture and palette state), and fails a recipe that names a
record without a source. Every record of a file must still be what this tree's `ff_build` builds from its key (`0
ff-stale`). `synthetic.bin` must hold at least one fixed-function pair; `conformance-x64.bin` was captured under
`shader.backend=msl`, whose fixed-function records keep no source (`--merge` drops them), and is held to that rule
once it is recaptured under `air`.

## Regenerating

Run from a checkout, with the cache kept per subtest by the runner and merged afterwards:

    cargo run -p mtld3d-core --features disk-cache --example emit_corpus -- --write-cache tests/d3d9/dxso-corpus/synthetic.bin
    sh dxmt/mtld3d-conformance.sh --keep-shader-cache <dir>/x64
    sh dxmt/mtld3d-conformance.sh --arch i686-arm64 --exe <x86 d3d9_test.exe> --keep-shader-cache <dir>/i686
    cargo run -p mtld3d-core --features disk-cache --example emit_corpus -- --merge tests/d3d9/dxso-corpus/conformance-x64.bin <dir>/x64/*.bin

(`--merge` for `conformance-i686.bin` over `<dir>/i686/*.bin`. It drops the records without a source and the recipes
naming them, and says how many on its first line.) A bump of `SHADER_CACHE_SCHEMA_VERSION` makes
`shader_cache::load` drop these files, and `emit_corpus --merge` refuses them: regenerate all three then.
